Replaced it with **recursive whitespace-gutter projection (classic X-Y cut)**: find full-width/full-height bands of paper-brightness pixels and cut on them, recursively. This only needs the *gutter* to be reliably brighter than the art, not the border to be reliably dark — much more robust to real scan artifacts. Verified 7/8/8 panels correctly on all 3 sample pages, matching Magi's own counts.

- 2026-09-22: User spotted (by eye, in `phase 1 output/page_04_magi_overlay.png`) that Magi's last panel box on page_04 was visibly undershooting the true panel — it started ~30px too low and clipped the top of a caption strip ("GOOD -- NOW LET'S HAUL..."). Root cause: that panel has a caption box with its own border sitting between the true page gutter and the panel art; Magi's raw box stopped partway into that caption rather than at the real gutter. Rather than just padding all boxes uniformly (which would loosen already-correct boxes too), added `snap_boxes_to_gutters()`: for each Magi box, search outward from each edge for a *genuine* whitespace gutter (a contiguous run of background-brightness rows/columns at least `min_gutter_px=8` wide) and snap to it. The `min_gutter_px=8` threshold specifically matters — a naive lower threshold (5px) was fooled by a narrow bright gap *inside* the caption box itself, snapping to the wrong, nearer "fake" gutter instead of the real one further out.
